02 / OUR IMPLEMENTATION

我们如何把这些能力接起来。

规划器做每次观测决策，跟踪器用反馈校正状态。
模型理解文字，预算守卫控制整个运行节奏。

Σ

SEASON-AWARE PLANNING

不只问“这一步赚多少”。

先估计剩余赛季能完成哪些目标，为光纤时间定价，再联合搜索指向、时长和分配。对以后仍要重拍的半截曝光，计入它占用未来时间的代价。

PLANNER.PY ↗
COARSE → FINE

先粗搜索，再精修

高价值目标与密集天区提供锚点，在附近搜索指向偏移，再细化最有希望的方案。

PRIORITY OVER TIME

优先级随赛季改变

必观测目标按以后来不及完成的风险加权；限时请求先判断可行性，再投入观测时间。

P

BAYESIAN STATE ESTIMATION

低收益，是天气还是故障？

贝叶斯滤波同时估计天气水平 W、仪器效率 η 和故障概率。天气影响完成度与程序档位，仪器效率只影响完成度，曝光反馈让两者逐步分开。

TRACKER.PY ↗
HAZARDS / POINTING

区分不同的异常

处理地形遮挡、局部天气、圆顶关闭与地震，用命中和未命中结果估计隐藏指向偏差。

LEDGER / RECOVERY

数据丢失后重建

账本可作废指定窗口并重放，再用引擎返回的最佳成绩校正状态，重新安排目标。

文

BOUNDED LANGUAGE REASONING

理解文字，影响有界。

模型提取日志事实、写夜间简报、裁决故障，并通过工具复盘赛季。答案经过代码校验，只在指定范围内生效；没有密钥或调用失败，依然按规则运行。

SUPERVISOR.PY ↗
GROUNDED FACTS

事实必须有来源

故障、维护和校准日程须引用原文行号，并通过时区、时间窗口与更正版本的校验。

PAUSE / WAIT / CONTINUE

调用也有时间成本

关键时点暂停并等待回答；单请求、限流退避、服务切换与工具协议回退控制失败影响。

t

CPU & WALL-CLOCK GUARD

跑完整季，才拿得到后面的分。

每卡有 900 秒 CPU 预算与 30 分钟真实时间上限。引擎随着曝光账本变大而变慢，守卫持续测量并预测剩余赛季需要的真实时间。

AGENT.PY ↗
FEWER / LONGER EXPOSURES

先少搜，再少做几步

预算吃紧时先降低搜索力度，再提高普通曝光的最短时长，用更少、更长的曝光跑完赛季。

VALIDATE / FALL BACK

固定档位与异常兜底

搜索力度按固定档位调整；发出前校验动作，决策异常则替换为一次等待。

LLM / DUTY LOG

值班日志

原文 → 有来源的故障与维护日程

LLM / BRIEFING

夜间简报

公报与预报 → 今晚的观测姿态

LLM / FAULT VERDICT

故障裁决

MODEL FAILURE HANDLING
9种假模型场景

为模型调用交付容错工具

假模型服务覆盖正常、工具协议回退、限流、慢响应、乱码、报错与超时等情况，检查可用答案能生效、失败时能继续运行。
